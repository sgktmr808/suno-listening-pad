# 試聴パッド (SUNO Listening Pad)

SUNO へ貼る3欄（**歌詞欄 / Style / Exclude Styles**）と、作詞家の**名前 / 個性 / 参照歌詞**を、iPhone から1タップでコピーするための
1ファイルのページ。**プロンプトそのものは持たない** — 手元の Markdown を読み込んで3欄に分解して並べるだけ。

👉 **https://sgktmr808.github.io/suno-listening-pad/**

外出先で聴き比べるための道具です。曲の生成条件（Weirdness / Style Influence / Duration / seed /
styleHash）も一緒に出るので、SUNO 側のつまみを合わせてから貼れます。

## 使い方

1. 試聴したい md を iPhone に置く（iCloud Drive など）
2. ページを開いて「md ファイルを選ぶ」（複数可）、または「フォルダごと読み込む」で追加する。渡せないときは本文を貼り付けてもいい
3. セットを選び、**歌詞欄 → Style → Exclude**の順にコピーして SUNO へ貼る（押した欄は色が変わるので、どこまで貼ったか見失わない）
4. 聴いたら判定（A / B / 差なし、単体セットは 当たり / 普通 / だめ）と所感を残す。A/B は **A と B それぞれに所感欄**がある
5. ヘッダの「記録」→ **「ファイルに保存」**。共有シートから「“ファイル”に保存」で、md を置いてあるフォルダ（iCloud など）へ書き戻す

書き出す md はこの形なので、そのまま元の試聴記録へ貼り込めます:

```markdown
## A/B 01 — … (s26_vocal_family_bias)
- 出典: `ab_20260909_..._01_s26_vocal_family_bias.md`
- 条件: Weirdness 20 / Style Influence 78 / Duration 5:15 / seed 11
- A — フラグ OFF の所感: 歌もの。声は指定どおり
- B — フラグ ON の所感: インストになった
- 判定: B
```

同じ Apple ID の Mac があるなら「コピーする」でも渡せます（ユニバーサルクリップボード）。

読み込んだ内容・判定・メモはその端末の `localStorage` にだけ残ります。サーバへは何も送りません。

## 作詞家モード

1. 上部の「作詞家」を選択します。
2. 「作詞家フォルダを読み込む」でデータフォルダを選ぶか、「作詞家データを読み込む」でJSON・Markdownを選びます。複数ファイルに対応しています。
3. 言語・名前・題材で絞り込み、1人開きます。
4. Sunoの「作詞家を作成」へ「名前」「個性」をそれぞれコピーします。
5. 「参照歌詞を追加」→「新しい歌詞」で参照歌詞を貼り付け、必要に応じて編集します。自作の歌詞に置き換えることもできます。
6. Sunoで保存し、歌詞作成時に選択。その曲の題材は別途指定します。

作詞家は歌詞の書き方を導く機能です。声質や編曲はVoiceやStyleで設定します。[Suno公式の説明](https://suno.com/release-notes/lyrics-improvements-on-web)

- JSONとMarkdownが混在するフォルダでも、同じ作詞家を重複登録しません。IDが同じ改訂版は更新します。旧形式は旧名と旧個性の一致で移行します。
- 試聴用のファイル選択から作詞家Markdownを選んだ場合も、作詞家モードへ読み込みます。
- 進捗は%で表示し、完了・失敗・リセット時に非表示に戻ります。
- 個性は240文字以内。参照歌詞は別欄です。旧版に参照歌詞がなければ、その旨を表示します。
- コピーに失敗した場合は本文を選択し、手動でコピーできます。
- データはこのブラウザに保存します。Sunoへの登録は手動です。作詞家のリセットは試聴セットやメモに影響しません。
- フォルダを選べない環境ではJSONまたは複数のMarkdownを選んでください。データは公開リポジトリには同梱しません。

## フォルダの追加とリセット

- 「ファイル」→「フォルダごと読み込む」で、サブフォルダを含む `.md` / `.markdown` をまとめて読み込みます（拡張子の大文字・小文字は問いません）。
- フォルダやファイルを選択した後、進捗バーと **0〜100%** を表示します。進捗は処理済みのMD件数と、読み取り中のファイルの進捗から計算します。読み取り後の解析・一覧反映が終わるまで100%にはしません。完了後はメーターを自動で非表示にし、読み込み方法と結果の件数だけを残します。エラーやリセット時もメーターを消します。ファイル選択画面でのフォルダ準備中は、アプリ側の進捗には含みません。
- Style / Exclude / 歌詞欄のどれかがあるMDだけを追加します。その他のファイル・対応欄のないMDは読み飛ばし、使用できたMD・対象外・読み込み失敗の件数を画面に表示します。
- 読み込み済みと内容・生成条件が同じセットは、ファイル名・フォルダ・タイトルが違っても重複としてスキップします。個別選択・フォルダ選択・本文貼り付けに対応し、同時に選択したファイル同士の重複も防ぎます。完了時に重複スキップのセット数を表示します。
- 重複判定では各バリアントのStyle・Exclude・歌詞（切り替え候補を含む）・注記と、設定・seed・styleHashを比較します。改行コードと欄の前後の空白は無視します。生成条件や内容が違うセットは別内容として扱います。
- 同じ相対パス・セットIDで内容が変わった場合は更新し、判定とメモを残します。重複としてスキップした場合も、既存の判定・メモ・出典は保持します。既に登録されている重複セットは自動削除しません。
- フォルダ選択に対応しないブラウザでは「md ファイルを選ぶ」で複数選択してください。
- 「ファイル」→「読み込みデータをリセット」で、確認後にこの端末のセット・判定・メモ・コピー済み状態を削除します。読み込み中の処理も取り消します。元のMDファイルは変更しません。必要な記録は先に「記録」から保存してください。
- 「読み込み済みの一覧へ」で追加前のセット一覧に戻れます。

## ジャンル・曲の種類で絞り込む

一覧上部の「ジャンル」と「曲の種類」を組み合わせて絞り込めます。曲の種類は「インスト」「歌もの」「未分類」です。「絞り込みを解除」で全件に戻ります。

- **ジャンルを名乗っている md は、そのジャンルで確実に絞り込みます**。試聴 md に `- 出典: genre \`city_pop\`（シティポップ）` の行があれば、その id をそのまま使います（選択肢に「(ジャンル指定)」と出ます）。
- 名乗っていない古い md だけ、Style・歌詞からの自動推定にかかります（選択肢に「(本文から推測)」と出ます）。この推定は Ambient、Pop、Rock、Jazz、Electronic、House、Hip-Hop などの粗いキーワードで、当たらないものは未分類になります。**`lo-fi vinyl crackle` のような制作質感の語に反応して別ジャンルへ入ることがあります**（283ジャンルで測ったところ 29% が未分類、22件が誤って Lo-fi に入りました）。ジャンルを名乗る md を使うのが確実です。
- 一覧上部の検索欄では、ジャンル名・題名・Style 本文を横断して探せます。**全角/半角・ひらがな/カタカナ・大文字小文字は区別しません**。空白で区切ると、区切った語を**全部含む**ものだけを出します。
- 分類はテキストからの判断です。実際の音源を判定する機能ではありません。Exclude欄は分類に使いません。
- A/Bセットは、両方の絞り込み条件を満たすバリアントがある場合に表示します。開くと該当する側を最初に表示し、A/B切り替えでほかの側も確認できます。
- 「前」「次」は絞り込み結果の中を移動します。「絞り込み一覧へ」で選択条件を保って一覧に戻ります。条件はページを開いている間だけ保持します。
- 絞り込みは表示だけを変えます。読み込み済みデータ・判定・メモの削除や変更は行いません。

## 読める Markdown

| 書き方 | 想定している元ファイル |
|---|---|
| `### Style` / `### Exclude Styles` / `### Lyrics Scaffold (…)` + コードブロック | A/B ペア |
| `**Style**` / `**Exclude Styles** — 空のまま` / `**Lyrics**` | 切り分けテスト |
| `## 使用したStyleプロンプト` + コードブロック、`Exclude Styles: …` の1行 | レビューシート |

- `## A — …` と `## B — …` の2節を持つファイルは、**1セット2バリアント**に畳んで A/B タブで切り替える
- **同じ節に歌詞欄が2つある**ファイル（`### Lyrics Scaffold`(構成だけ) と `### Lyrics`(歌える言葉に置き換えた版)）は、歌詞欄カードの上に **「構成だけ / 歌詞つき」の2択**が出る。**歌える行が多い方が既定**なので、開いてそのままコピーすれば歌詞入りが貼られる（行数もボタンに出る）。切り替えは曲ごとに覚える
- 値が無く「テスト3と同じ」のように書かれている欄は、**注記としてそのまま表示**する（空をコピーさせない）
- `差分` / `設定JSON` / `試聴記録` / `記入欄` などの節と、` ```diff ` / ` ```json ` のブロックは読み飛ばす
- 3欄がどれも無い節は出さない

## ジャンル解説（外部データ）

`index.html` と**同じ場所に `genres.json` を置くと**、曲を開いたときにそのジャンルの解説が読めます。
概要・成り立ち・どんな場の音楽だったか・代表的なアーティスト・代表的な楽曲が、**それぞれ出典リンクつき**で出ます。

- **解説はページに埋め込んでいません。** データは `genres.json` 側にあり、直すときはそのファイルだけ差し替えます。
- **置かなくても動きます。** 無いときは解説を出さないだけで、それ以外は従来どおりです。
- 対応づけは試聴 md の `- 出典: genre \`<id>\`` の行。名乗っていない md には解説が出ません。
- アーティスト名・楽曲名・年号は**実際に開いて本文で確認できたものだけ**が入っています。確認できなかったことは各ジャンルの「確かめられなかったこと」に書いてあります。確度（高/中/低）も併記します。
- 作る側: SUNO Prompt Composer 側の `node scripts/make_genre_notes.cjs --notes <調査結果> --write` が `outputs/pad/genres.json` を書きます。出典URLの無いアーティスト・楽曲があると書き出しに失敗します。

## 中身

`index.html` 1枚と、任意で `genres.json`（ジャンル解説の外部データ）。ビルドもサーバも要りません。
外部から読むのは Google Fonts だけなので、ローカルに置いて `open index.html` でも動きます
（`genres.json` は同じ場所から読みます）。
